## 1. 项目鸟瞰：到底在做什么

### 1.1 项目是干嘛的

我们要做一个**会玩简化版扑克的 AI**。这个扑克的规则是：

- 两人对战，最多打 3 局（BO3：先赢 2 局算总赢）
- 每局每人发 5 张牌：**2 张暗牌**（自己看得见，对手看不见）+ **3 张明牌**（双方都看得见）
- 每局两个阶段：
  - **FOLD 阶段**：双方同时决定「弃牌（fold）」还是「玩（play）」。任一人 fold 那局立即结束
  - **REDRAW 阶段**：双方可以"丢牌换新"，每人有 7 张换牌**预算**贯穿整个对局（不是每局都补满的）。可以**反复换**直到双方都说 STOP
- 不下注，只比牌力。所以胜负是 -1 / 0 / +1（输 / 平 / 赢）

### 1.2 为什么不能简单写规则告诉 AI 怎么打

因为这是**信息不完美博弈**——你不知道对手的暗牌。理论上「最优策略」必须是**混合策略**（有时这么打、有时那么打、按某个概率分布），否则会被对手利用。

经典强化学习（Q-Learning）在完美信息游戏（象棋、围棋）效果好，但在不完美信息博弈下会陷入"对手能猜到我下一步"的循环。**CFR**（Counterfactual Regret Minimization，反事实后悔最小化）是 2007 年提出、专为不完美信息博弈设计的算法——德州扑克 AI 都用这家族算法。

### 1.3 这个项目的整体架构

```
原始代码（不动）：           现代化重写（本项目）：
─────────────────           ─────────────────────
Backend/  (Flask)           cfr/                  ← 我们的工作目录
Frontend/ (Web UI)          ├── env/   游戏规则 + 状态
model/    (Q-Learning AI)   ├── agent/ CFR 算法

```

`cfr/` 是一个**独立的 Python 模块**，自己跑训练、自己有测试，最后给原本的 Backend 提供一个"训练好的 AI 推理接口"。但本次重构**没有把 cfr/ 接进 Backend**（Phase 5 不在范围内）。

## 3. 数据流：一次训练 + 一次对战的全过程

**记住这张图**，后面所有代码都在为它服务：

### 3.1 训练时（一次 iteration）

```
1. trainer.py 创建一局新游戏 PokerGame(seed=...)
                    ↓
2. trainer.py 调用 mccfr.outcome_sampling(game, traverser, table, info_set_fn, rng)
                    ↓
3. outcome_sampling 递归地走一条从开局到终局的路径，期间：
   - 在每个节点：
     a. 看当前玩家是谁
     b. 算出他的 observation（用 game.observation(player)）
     c. 把 observation 压成 info_set_key（用 info_set.encode_info_set）
     d. 从 RegretTable 查这个 key 的当前 strategy（regret matching）
     e. 按 strategy 采样一个动作往下走
   - 走到终局后递归回溯：
     f. 更新 RegretTable 的 regret（"这个动作是不是亏了？"）
     g. 更新 RegretTable 的 cumulative_strategy（"我这次用了什么策略？"）
                    ↓
4. trainer.py 检查是否到了日志/存档点：
   - 写一行 CSV log
   - 把 RegretTable pickle 到 .pkl 文件
                    ↓
5. 回到第 1 步，跑下一个 iteration
```

跑 1M iter 大约 4 小时，期间会存 100 个 checkpoint。

### 3.2 对战时（推理）

```
1. cfr_agent.CFRAgent.from_checkpoint("xxx.pkl") 加载训练好的 table
                    ↓
2. play.play_match(cfr_agent, opponent, num_games=500) 开始打
                    ↓
3. 每局：PokerGame.is_terminal() 为 False 时循环：
   a. 看当前玩家是谁
   b. 调用对应 agent 的 .act(game, player)
   c. agent 内部：
      - 算 observation → encode_info_set → 查 average_strategy
      - 按 average_strategy 采样动作（注意：用 average，不是 regret matching）
   d. game.apply(action) 推进状态
                    ↓
4. 终局后 game.utility(player) 给出 -1/0/+1
                    ↓
5. 统计胜负，下一局
```

**关键差别**：训练时用 `get_strategy`（regret matching 当前迭代值），推理时用 `average_strategy`（所有迭代的平均，是 Nash 收敛的量）。这是 CFR 最容易写错的地方之一。

## Part 1: env/ —— 游戏本身

### 1.1 `env/poker_rules.py` —— 牌型评估

**作用**：拿到 5 张牌，告诉你这副牌的等级（高牌/对子/三条/.../皇家同花顺）。

**两个公开函数**：

```python
get_rank_suit(card: int) -> (rank, suit)
    # 输入：一个 0-51 的整数
    # 输出：(rank 0-12, suit 0-3)
    # rank: 0=2, 1=3, ..., 11=K, 12=A（注意 2 是 0，A 是 12，方便排序）
    # suit: 0=Spades(黑桃), 1=Hearts(红心), 2=Diamonds(方块), 3=Clubs(梅花)

evaluate_hand(hand: List[int]) -> (handtype, tiebreakers)
    # 输入：5 张牌（0-51 整数列表）
    # 输出：(handtype 0-9, tiebreaker 列表)
    # handtype:
    #   0=高牌, 1=一对, 2=两对, 3=三条, 4=顺子,
    #   5=同花, 6=葫芦, 7=四条, 8=同花顺, 9=皇家同花顺
```

**为什么牌的编号要这么搞**：用 0-51 一个整数表示一张牌，`card % 13` 是点数（0-12，原始 A=0、K=12），`card // 13` 是花色。**调整后 rank** 把 2 放到 0、A 放到 12，这样比大小不用特判。

**为什么要返回 tiebreaker 列表**：比如两个对子要比剩下的 kicker（垫脚牌）；两个同花要比最大牌、然后第二大、依此类推。用一个 list 装着，Python 可以直接 `>` 比较 list（按字典序）。

`compare_hands(h1, h2)` 返回 1/2/0（h1赢/h2赢/平），就是先比 handtype，再字典序比 tiebreakers。

**它和谁打交道**：被 `env/game.py` 在 `_resolve_round()` 调用（决定谁赢那一局）；被 `eval/rule_agents.py` 调用（让规则 agent 判断自己手牌强弱）。

### 1.2 `env/observation.py` —— "玩家能看到什么"

**作用**：定义一个不可变的数据结构，描述"在某个决策点，玩家 P 看到的所有信息"。这是 CFR 算法和游戏的**唯一接口**——CFR 只能通过 Observation 看世界。

```python
@dataclass(frozen=True)
class Observation:
    # 自己（看得全）
    my_hand: Tuple[int, ...]                       # 5 张牌
    my_remaining_redraws: int                       # 剩余换牌预算
    my_round_wins: int                              # 已赢局数
    my_fold_history: Tuple[bool, ...]               # 过去几局有没有 fold
    my_redraw_history: Tuple[Tuple[int, ...], ...]  # 过去几局的换牌动作
    my_redraw_actions_this_round: Tuple[int, ...]   # 本局已经做了哪些 redraw
    my_redraw_done: bool                            # 本局是否已经 STOP

    # 对手（只看得到公开信息）
    opp_visible_cards: Tuple[Optional[int], ...]    # 5 个位置，暗牌处是 None
    opp_remaining_redraws: int
    opp_round_wins: int
    opp_fold_history: Tuple[bool, ...]
    opp_redraw_history: Tuple[Tuple[int, ...], ...] # 对手的过去换牌（只显示张数）
    opp_redraw_counts_this_round: Tuple[int, ...]
    opp_redraw_done: bool
    opp_fold_this_round: Optional[bool]             # 同时出牌前是 None

    # 游戏状态
    round_num: int
    phase: str                                      # 'fold' 或 'redraw'
    current_player: int                             # 现在轮到谁
```

**`@dataclass(frozen=True)` 啥意思**：Python 的「数据类」装饰器。`frozen=True` 让它不可修改（hashable，可以当 dict 的 key）。比手写 `__init__` 简洁。

**为什么对手暗牌位置是 `None` 而不是某个特殊数字**：物理上的"看不见"——CFR 不能写 `if opp_card == -1` 之类的 hack 来作弊。`None` 进入 info_set 编码后会直接产生不同的 key，强制 CFR 在缺少信息时学一个混合策略。

**为什么 `opp_redraw_counts_this_round` 只给"张数"不给 bitmask**：对手换了哪几张牌是私密信息（对手知道自己要换哪几个位置但你不知道），但**换了几张**是公开的（你看见他丢了几张牌）。

### 1.3 `env/game.py` —— 主游戏类（**核心**）

这是整个项目最重要的文件之一。它实现完整的扑克游戏。

#### 1.3.1 关键常量

```python
HOLE_INDICES = (0, 1)              # 前 2 张是暗牌（手中）
FACE_UP_INDICES = (2, 3, 4)        # 后 3 张是明牌（桌上）
NUM_PLAYERS = 2
HAND_SIZE = 5
DECK_SIZE = 52
INITIAL_REDRAWS = 7                # 每个玩家一开始有 7 张换牌预算
MAX_ROUNDS = 3
REDRAW_ACTION_SPACE = 32           # 2^5 = 32（5 张牌的 bitmask）
REDRAW_ACTION_STOP = 0             # action 0 = "STOP"，因为 bin(0)=000000，丢 0 张
FOLD_ACTION_PLAY = 0
FOLD_ACTION_FOLD = 1
```

**什么是 bitmask**：用一个二进制数的每一位表示"是否选中第 i 个东西"。比如 `0b10100`（十进制 20）= 「选中第 2 位和第 4 位」。在这里用来表示"换哪几张牌"：
- action = 0b00000 = 0 → 不换任何牌（STOP）
- action = 0b00001 = 1 → 只换第 0 张
- action = 0b00111 = 7 → 换前 3 张
- action = 0b11111 = 31 → 换全部 5 张

所以 REDRAW 阶段共 32 个合法动作（实际有些超过预算就非法，由 `legal_actions()` 过滤）。

#### 1.3.2 状态结构

```python
class PokerGame:
    def __init__(self, seed):
        self._rng = random.Random(seed)
        self.reset()

    def reset(self):
        self.round_num = 1
        self.round_wins = [0, 0]              # [p0_wins, p1_wins]
        self.remaining_redraws = [7, 7]
        self.fold_history = [[], []]          # 每个玩家过去几局有没有 fold
        self.redraw_history = [[], []]        # 每个玩家过去几局的 redraw 序列
        self._terminal = False
        self._start_round()
```

`_start_round()`：洗牌、发牌、把本局状态清零。

#### 1.3.3 CFR 接口（所有外部代码靠这 5 个方法操作游戏）

```python
current_player()  -> int          # 0 或 1，-1 表示已终局
is_terminal()     -> bool         # 是否游戏结束
legal_actions()   -> List[int]    # 当前玩家的合法动作
apply(action)     -> None         # 执行动作，推进状态
utility(player)   -> float        # 终局时返回 -1/0/+1
observation(player) -> Observation # 该玩家看到的世界
```

这是 OpenSpiel 风格的标准博弈接口——所有 CFR 算法只依赖这 5 个方法。

#### 1.3.4 同时出牌怎么建模

扑克 FOLD 阶段是**同时出牌**，但博弈树天生是序列的。解决方案：

```python
def apply(self, action):
    ...
    if self.phase == Phase.FOLD:
        self.fold_this_round[player] = (action == FOLD_ACTION_FOLD)
        if self._waiting_for == 0:
            self._waiting_for = 1       # P1 选完，轮到 P2
        else:
            self._fold_revealed = True  # 两人都选完了，揭示
            if any(self.fold_this_round):
                self._resolve_round()
            else:
                self.phase = Phase.REDRAW
                self._start_redraw_iter()
```

**关键点**：P1 选完之后，P2 的 `observation()` 中 `opp_fold_this_round` 仍然是 `None`（看不见 P1 的选择）。直到两人都选完才同时揭示。这样建模成序列但信息上仍是同时出牌。

#### 1.3.5 REDRAW 阶段的迭代结构

REDRAW 阶段会反复进行直到双方都 STOP：

```
iter 1: P1 选 bitmask（可能换 2 张）→ P2 选 bitmask（可能 STOP）→ 揭示双方动作
iter 2: 如果有人没 STOP，继续；P1 选 → P2 已 STOP 不再选 → 揭示
iter 3: ... 直到两人都 STOP
```

`_finalize_iter()` 同时处理两个玩家在本 iter 的待定动作（pending），其中：
- 如果 action=0（STOP）：标记 `redraw_done[p] = True`，以后不用再决策
- 否则：用 bitmask 找出要换的位置，从牌堆顶部抽新牌替换，扣预算

```python
indices = [i for i in range(HAND_SIZE) if (action >> i) & 1]
for idx in indices:
    self.hands[p][idx] = self._deck[self._deck_pointer]
    self._deck_pointer += 1
self.remaining_redraws[p] -= len(indices)
```

`(action >> i) & 1` 是位运算："action 的第 i 位是不是 1"。

#### 1.3.6 `observation(player)` —— 关键的"信息脱敏"

```python
opp_cards = []
for i in range(HAND_SIZE):
    if i in FACE_UP_INDICES:           # 明牌位置
        opp_cards.append(self.hands[opp][i])
    elif self._terminal and self._showdown_revealed:  # 终局时揭牌
        opp_cards.append(self.hands[opp][i])
    else:
        opp_cards.append(None)         # 看不见
```

这里**强制隐藏对手暗牌**。任何 agent（包括 CFR、规则 agent）都只能通过 `observation()` 看世界，不能直接读 `game.hands[opponent]`。这就保证了"信息不完美博弈"的 invariant。

### 1.4 `env/kuhn.py` —— 玩具游戏验证算法

**Kuhn Poker 是什么**：1950 年 Harold Kuhn 提出的最小化扑克。3 张牌（J/Q/K），每人发 1 张，最多 3 个动作回合，**总共只有 12 个信息集**。

**为什么要实现它**：因为它**有解析 Nash 解**（已知 game value = -1/18，可精确计算 exploitability）。如果我们的 CFR 实现在 Kuhn 上能收敛到 exploit ≈ 0，那算法本身是对的。后面在主游戏上不收敛，就一定是工程问题（info set 太大、采样方差等）而不是算法 bug。

**接口完全相同**：`current_player`/`is_terminal`/`legal_actions`/`apply`/`utility` 五件套——CFR 算法可以完全复用。

**唯一的额外方法**：`info_set_key(player)` 直接返回字符串（`"2:01"` 表示"我手牌是 K，历史是 check-bet"），不用走 Observation 那套。这是因为 Kuhn 太简单，省略 Observation 层。

### 2.1 `agent/regret_table.py` —— CFR 的"记忆"

CFR 学的不是神经网络，是**两张表**：

1. **regrets**：`{info_set_key: {action: cumulative_regret}}`——"如果之前我每次都选 a 而不是当时选的策略，我会多/少多少回报？"
2. **cumulative_strategy**：`{info_set_key: {action: cumulative_prob}}`——"过去所有迭代里，我在这个 info set 用 a 的概率累加起来是多少？"

```python
class RegretTable:
    def __init__(self):
        self._regrets = defaultdict(_float_dict)
        self._cumulative_strategy = defaultdict(_float_dict)
```

**`defaultdict` 是啥**：Python 的字典变种。如果你 `d["不存在的key"]`，普通 dict 会报错，`defaultdict` 会自动创建一个默认值。这里用 `defaultdict(_float_dict)`：外层 key 不存在时自动创建一个 `defaultdict(float)`；内层 action key 不存在时自动创建 0.0。意味着 `table._regrets["new_key"][3] += 0.5` 不会报错。

**为什么用模块级函数 `_float_dict` 而不是 lambda**：`lambda: defaultdict(float)` 看起来更简洁，但 lambda **不能被 pickle 序列化**。整个 RegretTable 要 pickle 存盘，所以必须用具名函数。

#### 2.1.1 三个核心方法

```python
def get_strategy(self, info_set, legal) -> Dict[int, float]:
    """Regret matching: P(a) ∝ max(0, regret(a))。
    这是 CFR 训练时用的'当前迭代策略'。"""
    entry = self._regrets.get(info_set, {})
    positive = {a: max(0.0, entry.get(a, 0.0)) for a in legal}
    total = sum(positive.values())
    if total > 0:
        return {a: p / total for a, p in positive.items()}
    return {a: 1.0 / len(legal) for a in legal}   # 全 0 时回退均匀
```

这就是 **Regret Matching** 算法：哪个动作的累计后悔（regret）越大，就越倾向于多选它。负 regret 的动作概率为 0。如果都是负 / 都是 0，就均匀随机。

```python
def update_regret(self, info_set, action, delta) -> None:
    self._regrets[info_set][action] += delta

def update_cumulative_strategy(self, info_set, strategy) -> None:
    for a, p in strategy.items():
        self._cumulative_strategy[info_set][a] += p
```

简单的累加。

```python
def average_strategy(self, info_set, legal) -> Dict[int, float]:
    """归一化的 cumulative strategy。这是 CFR 推理时用的 Nash-收敛策略。"""
    entry = self._cumulative_strategy.get(info_set, {})
    cumul = {a: entry.get(a, 0.0) for a in legal}
    total = sum(cumul.values())
    if total > 0:
        return {a: c / total for a, c in cumul.items()}
    return {a: 1.0 / len(legal) for a in legal}
```

**关键 CFR 数学事实**：迭代趋近无穷时，**累计策略的归一化（average strategy）会收敛到 Nash 均衡**，而当前迭代的 regret matching 输出**不会**收敛（它会一直震荡）。所以**训练时用 regret matching，推理时用 average strategy**——记不住这点就把整个 CFR 写废了。

#### 2.1.2 用 `.get()` 而不是 `[...]` 读 defaultdict

```python
entry = self._regrets.get(info_set, {})   # ✓ 不会创建新条目
# vs
entry = self._regrets[info_set]           # ✗ 会自动创建空条目
```

为啥重要：如果评估代码（比如算 exploitability 时）读 1 万个 info set，前者读完后 table 大小不变；后者会**额外创建 1 万个空条目灌爆**。Phase 3 因此踩过坑。

### 2.2 `agent/info_set.py` —— 把 Observation 压成 key

**问题**：Observation 是个复杂对象，CFR 表的 key 需要是字符串（或可哈希值）。怎么把 Observation 变成 key？

**Naive 做法**：`repr(observation)` 全部信息塞进去。

**问题**：信息太多 → info set 数爆炸 → 每个 info set 几乎不被重复访问 → 学不到东西。

**正确做法**：**抽象（abstraction）**。把"在策略上等价"的状态合并成同一个 key。

#### 2.2.1 当前的抽象设计

```python
def encode_info_set(obs: Observation) -> str:
    hand_rank, top_card = _hand_rank_and_top(obs.my_hand)
    dominant_suit, suited_mask = _suited_mask(obs.my_hand)
    straight_mask, draw_type = _straight_features(obs.my_hand)
    opp_face_up = _opp_face_up_features(obs.opp_visible_cards, dominant_suit)

    key = (
        hand_rank, top_card, suited_mask, straight_mask, draw_type,
        opp_face_up,
        obs.my_remaining_redraws, obs.opp_remaining_redraws,
        obs.my_round_wins, obs.opp_round_wins,
        obs.phase, obs.round_num,
        obs.my_redraw_actions_this_round,
        obs.opp_redraw_counts_this_round,
        obs.my_redraw_done, obs.opp_redraw_done,
        obs.opp_fold_this_round,
        obs.my_fold_history, obs.opp_fold_history,
        obs.my_redraw_history, obs.opp_redraw_history,
    )
    return repr(key)
```

把手牌抽象成 **7 个特征**（hand_rank、top_card、suited_mask、straight_mask、draw_type、opp_face_up），而不是 5 个具体的牌。两副不同的牌如果特征都一样，CFR 会认为它们是同一个决策点。

**例子**：
- 手牌 `[J♠, J♥, 3♣, 4♦, 7♠]` → hand_rank=1（一对）、top_card=J、suited_mask=(0,0,0,0,0)
- 手牌 `[K♠, K♥, 2♦, 5♣, 9♠]` → hand_rank=1、top_card=K、suited_mask=(0,0,0,0,0)

不一样的 top_card，所以仍是不同 info set。但 `[J♠, J♥, 3♣, 4♦, 7♠]` 和 `[J♣, J♦, 2♠, 5♣, 8♥]` 这俩**会**被合并（特征相同）——它们策略上确实差不多（都是一对 J，没听牌，没同花）。

#### 2.2.2 几个抽象函数细节

`_suited_mask`：找最多的花色，如果 ≥3 张同花，标记这些位置。例如 4 张黑桃 + 1 张红桃 → mask=(1,1,1,1,0)。

`_straight_features`：识别顺子潜力，区分**两头顺**（open-ended，~17% 中）vs **嵌张**（gutshot，~8.5% 中）。这关系到要不要继续换牌追顺子。

`_opp_face_up_features`：对手 3 张明牌，按 (rank, 是否与我同花色) sorted 后存。`sorted` 让顺序无关——`[K♠, 5♥, 9♣]` 和 `[9♣, K♠, 5♥]` 编码相同。

#### 2.2.3 这个文件踩的坑

**当前 4.36M info sets / 1M iter = 学不动**（见诊断报告）。最大问题是 `my_redraw_history` 这类"过去几局的具体动作序列"基数太高——历史是沉没成本，对当前决策不该影响，应该剔除。这是诊断报告 §6.1 推荐的修复方向。

### 2.3 `agent/mccfr.py` —— CFR 算法本体

两个函数：`external_sampling`（用于 Kuhn）和 `outcome_sampling`（用于主游戏）。

#### 2.3.1 External Sampling（Kuhn 用）

```python
def external_sampling(game, traverser, regret_table, info_set_fn, rng):
    if game.is_terminal():
        return game.utility(traverser)

    current = game.current_player()
    info_set = info_set_fn(game, current)
    legal = game.legal_actions()
    strategy = regret_table.get_strategy(info_set, legal)

    if current == traverser:
        # Traverser 节点：枚举所有动作
        action_values = {}
        for a in legal:
            child = copy.deepcopy(game)
            child.apply(a)
            action_values[a] = external_sampling(child, traverser, ...)
        node_value = sum(strategy[a] * action_values[a] for a in legal)
        for a in legal:
            regret_table.update_regret(info_set, a, action_values[a] - node_value)
        regret_table.update_cumulative_strategy(info_set, strategy)
        return node_value
    else:
        # 对手节点：按 strategy 采样一个动作
        ...
        return external_sampling(child, traverser, ...)
```

**关键思想**：
- 在 **traverser**（当前学习的玩家）的节点，**枚举所有动作**，递归计算每个动作的子树价值
- 在**对手节点**，只按对手策略**采样一个动作**往下走（不枚举）
- regret = "如果我之前都选 a 的话回报"（action_value）减去"我当时的混合策略期望回报"（node_value）
  - regret > 0 → 当时这么选亏了 → 以后多选 a
  - regret < 0 → 当时这么选反而好 → 以后少选 a

**为什么 Kuhn 能用**：Kuhn 只有 2 个动作，枚举开销低。

**为什么主游戏不能用**：主游戏 REDRAW 阶段最多 32 个动作，每次枚举都 deepcopy 一遍游戏状态 + 递归。tree branching = 32^depth 直接爆炸。

#### 2.3.2 Outcome Sampling（主游戏用）

```python
def outcome_sampling(game, traverser, regret_table, info_set_fn, rng, epsilon=0.6):
    return _os_episode(game, traverser, ..., my_reach=1.0, opp_reach=1.0,
                       sample_reach=1.0, epsilon=epsilon)
```

OS 思想：**只采样一条从根到终局的轨迹**，不枚举。每个节点都只选一个动作。代价：每条轨迹给的"梯度信号"是有偏的，必须用 **importance sampling 修正**才能保证收敛到正确的 regret。

```python
def _os_episode(game, traverser, regret_table, ..., my_reach, opp_reach, sample_reach, epsilon):
    if game.is_terminal():
        return game.utility(traverser)

    current = game.current_player()
    sigma = regret_table.get_strategy(info_set, legal)
    n = len(legal)

    if current == traverser:
        # ε-explore：保证每个动作至少 ε/n 概率被采到（否则可能永远学不到某些动作）
        sample_dist = {a: epsilon / n + (1.0 - epsilon) * sigma[a] for a in legal}
    else:
        sample_dist = sigma

    a_star = rng.choices(actions, weights=weights, k=1)[0]
    p_sample = sample_dist[a_star]

    # Reach probability 跟踪
    if current == traverser:
        new_my = my_reach * sigma[a_star]
        new_opp = opp_reach
    else:
        new_my = my_reach
        new_opp = opp_reach * sigma[a_star]

    child = copy.deepcopy(game)
    child.apply(a_star)
    child_value = _os_episode(child, ..., sample_reach=sample_reach * p_sample, ...)

    # Importance sampling 修正
    sampled_corrected = child_value / p_sample
    value_estimate = sigma[a_star] * sampled_corrected

    if current == traverser:
        # 更新 regret
        cf_value = value_estimate * opp_reach / sample_reach
        for a in legal:
            cf_action_value = (sampled_corrected if a == a_star else 0.0) \
                              * opp_reach / sample_reach
            regret_table.update_regret(info_set, a, cf_action_value - cf_value)
        # 更新 cumulative strategy
        increment = {a: my_reach * sigma[a] / sample_reach for a in legal}
        regret_table.update_cumulative_strategy(info_set, increment)

    return value_estimate
```

**几个关键量**：
- `my_reach`：从根到当前节点，traverser 自己策略乘积（"我按 σ 走到这里的概率"）
- `opp_reach`：对手策略乘积
- `sample_reach`：实际采样路径的概率乘积（用于 importance correction）

**为什么需要 importance correction**：我们只看到一条采样轨迹的结果，但要估计**期望**回报。如果某条轨迹被采样到的概率是 p，那它的回报要乘 `1/p` 才是无偏估计——这就是 IS 修正。

**ε-explore 的作用**：保证 `sample_dist[a] >= ε/n`。否则一旦 σ 把某动作概率压到 0，那条路径就再也不会被采样，永远学不到它的真实价值。

**当前的 bug**：ε=0.6 + 32 action + depth 6 → `sample_reach` 最小可达 10⁻¹¹ → `1/sample_reach` 爆炸到 10¹⁰ → 单次访问的 cumulative_strategy 增量主宰整个累积。详见诊断报告 §4。

### 4.1 `eval/exploitability.py` —— Kuhn 精确 exploitability

**Exploitability 是啥**：衡量一个策略 σ 离 Nash 均衡多远。

$$\text{exploit}(\sigma) = BR_0(\sigma_1) + BR_1(\sigma_0)$$

其中 `BR_p(opp_strategy)` 是玩家 p 对对手策略的**最佳响应价值**（best response）——"如果我能针对对手最优出招，我的期望回报"。

在 Nash 时 exploit = 0（双方都已经最优响应对方）。距离 Nash 越远，BR 给的便宜越多。

**Kuhn 的精确算法**：每个玩家 6 个信息集，每个信息集 2 个动作 → 64 个纯策略候选。**枚举全部 64 个**，挑最优。

```python
def _br_value(traverser, regret_table):
    info_sets = _enumerate_info_sets(traverser)  # 6 个

    def opp_avg(info_set_tuple):
        ...
        return regret_table.average_strategy(key, [CHECK_FOLD, BET_CALL])

    best = -inf
    n = len(info_sets)
    for bits in range(2 ** n):   # 64 个纯策略
        br_strategy = {info_sets[i]: (bits >> i) & 1 for i in range(n)}
        total = sum(_value_at_node(hands, (), traverser, opp_avg, br_strategy) for hands in _DEALS)
        avg = total / len(_DEALS)
        if avg > best: best = avg
    return best
```

**为什么 BR 必须以 info set 为单位枚举（而不是直接 max 每个节点）**：因为 BR 也是有信息约束的策略——不能针对对手的私密信息作弊。"在我看到 K 但不知道对手是 J 还是 Q 时" 这是一个 info set，必须用**同一个**动作回应。Naive max 会让 BR "偷看"对手的牌。

**Kuhn 训练 2 万 iter 后 exploit ≈ 0.01**（理论 Nash 是 0）——这是算法正确的金标准。

### 4.2 `eval/sampled_br.py` —— 主游戏的采样 BR

主游戏 4M 信息集，无法枚举 BR。退而求其次：**采样 1-ply BR**：

```
对每局游戏：
    p 用 sampled BR 玩，opp 用 sigma_avg 玩
    p 在每个决策点：
        枚举所有合法动作 a
        对每个 a，rollout K 次（K=5），双方都用 sigma_avg 走完，平均终局效用
        选效用最大的 a
    opp 全程用 sigma_avg
N 局求平均（N=200），就是 BR_p_value 的估计
```

```python
def _greedy_br_action(game, player, table, num_rollouts, rng):
    best_q = -inf
    best_a = None
    for a in game.legal_actions():
        total = 0.0
        for _ in range(num_rollouts):
            child = copy.deepcopy(game)
            child.apply(a)
            total += _rollout_with_avg(child, player, table, rng)
        q = total / num_rollouts
        if q > best_q:
            best_q, best_a = q, a
    return best_a
```

**这是一个下界**：因为 p 自己只往后看 1 步、之后又退回到 sigma_avg。真实 BR 会更狠（深度搜索每一步）。但作为训练进度指标够用——如果连这个松松的下界都不下降，那 σ 肯定没收敛。

**当前训练实测**：exploit ≈ 1.7-1.8 持平，没下降趋势（详见诊断报告 §2）。

### 4.3 `eval/rule_agents.py` —— 5 个规则基线

所有 agent 都实现统一接口 `act(game, player) -> int`，**只读 `game.observation(player)`**——绝不偷看 `game.hands[opponent]`。

| Agent | 行为 | 用途 |
|---|---|---|
| `RandomAgent` | 在 `legal_actions()` 里均匀随机 | 最弱基线 |
| `AlwaysCallAgent` | 永远 action=0（PLAY / STOP） | §4.5.5 验证：fold 弱占优，永远 play+STOP 就能秒大多数对手 |
| `TightAgent` | 高牌就 fold；有对子就 STOP；否则丢 junk | 故意暴露 fold 弱占优 → 被 CFR 吊打 |
| `LooseAgent` | 永不 fold；hand_rank<3 就激进 redraw | 反向极端 |
| `HeuristicAgent` | fold 仅当我很弱且对手 face-up 强（≥Q） + 保留 1 张 redraw 给后续局 | 最像人 |

#### 4.3.1 两个辅助函数

```python
def _junk_indices(hand):
    """找出不属于任何对子/三条/同花组的牌的位置 —— 这些是垃圾牌可以换。"""
    ranks = [get_rank_suit(c)[0] for c in hand]
    suits = [get_rank_suit(c)[1] for c in hand]
    rank_counts = Counter(ranks)
    suit_counts = Counter(suits)
    dom_suit, dom_count = suit_counts.most_common(1)[0]
    return [
        i for i in range(HAND_SIZE)
        if rank_counts[ranks[i]] < 2          # 不在任何对子里
           and not (dom_count >= 4 and suits[i] == dom_suit)  # 不在 4+ 同花里
    ]

def _redraw_action_from_indices(indices, budget):
    """把想换的位置列表 + 预算 → 合法 bitmask。"""
    if not indices or budget <= 0:
        return REDRAW_ACTION_STOP
    return sum(1 << i for i in indices[:budget])
```

`sum(1 << i for i in indices[:budget])` 把 `[0, 2]` 变成 `0b00101 = 5`。

#### 4.3.2 为什么要有这些 baseline

CFR 真正训出来后，对每个 baseline 的胜率是**最直观的强度指标**：

- **vs Random** 必须大胜（否则连基本牌力都没学到）
- **vs Tight** 必须 ≥ 70%（CFR 应学到对手 fold 倾向就 PLAY 偷局）
- **vs AlwaysCall** 是关键指标——能不能学到永不 fold（§4.5.5）
- **vs Heuristic** 才是真正的对手测试

诊断报告里展示了**未训练 vs 训练后**几乎无差别——证明训练没收敛。

### 4.4 `eval/cfr_agent.py` —— 推理用的 CFR agent

```python
class CFRAgent:
    name = "cfr"

    def __init__(self, table: RegretTable, seed=0):
        self._table = table
        self._rng = random.Random(seed)

    @classmethod
    def from_checkpoint(cls, path, seed=0) -> "CFRAgent":
        payload = load_checkpoint(path)
        return cls(payload["regret_table"], seed=seed)

    def act(self, game, player):
        obs = game.observation(player)
        key = encode_info_set(obs)
        legal = game.legal_actions()
        strategy = self._table.average_strategy(key, legal)
        actions = list(strategy.keys())
        weights = [strategy[a] for a in actions]
        return self._rng.choices(actions, weights=weights, k=1)[0]
```

**全部代码就这么短**。三个关键点：

1. **用 `average_strategy` 不是 `get_strategy`**——这是 CFR 推理的 Nash 收敛量
2. **没见过的 info set 自动回退 uniform**（在 `average_strategy` 内部处理）
3. **`from_checkpoint` 是 classmethod**——`CFRAgent.from_checkpoint("xxx.pkl")` 一行加载

### 4.5 `eval/play.py` —— 对战循环

```python
def play_match(agent_a, agent_b, num_games, seed=0):
    rng = random.Random(seed)
    a_wins = b_wins = ties = 0
    total_a_utility = 0.0

    for g_idx in range(num_games):
        game = PokerGame(seed=rng.randint(0, 2**31 - 1))
        a_seat = g_idx % 2                          # 交替座位
        seats = {a_seat: agent_a, 1 - a_seat: agent_b}

        while not game.is_terminal():
            p = game.current_player()
            action = seats[p].act(game, p)
            game.apply(action)

        u_a = game.utility(a_seat)
        total_a_utility += u_a
        if u_a > 0: a_wins += 1
        elif u_a < 0: b_wins += 1
        else: ties += 1

    return {"a_wins": ..., "b_wins": ..., "ties": ...,
            "a_avg_utility": total_a_utility / num_games, "num_games": num_games}
```

**关键设计**：`a_seat = g_idx % 2` 让 agent_a 偶数局坐 seat 0、奇数局坐 seat 1。**中和先手优势**——PokerGame 里 P0 永远先在 FOLD 阶段决策，这是位置劣势/优势取决于策略。不交替的话评估结果有偏。

`Protocol` 是 Python 3.8+ 的「鸭子类型」（structural typing）：任何有 `act(game, player) -> int` 方法和 `name` 属性的对象都算 Agent，不用显式继承。

```python
def run_match(cfr_agent, human_seat, game_seed):
    game = PokerGame(seed=game_seed)
    cfr_seat = 1 - human_seat

    while not game.is_terminal():
        cur = game.current_player()
        if cur == human_seat:
            a = human_act(game, human_seat)
        else:
            a = cfr_agent.act(game, cfr_seat)
            # 把 AI 的动作翻译成可读字符串
            phase_name = game.phase.value
            if phase_name == "fold":
                a_str = "PLAY" if a == 0 else "FOLD"
            else:
                a_str = "STOP" if a == 0 else f"redraw {[i for i in range(5) if (a >> i) & 1]}"
            print(f"  [AI acts: {a_str}]")
        game.apply(a)

    # 终局揭示双方手牌
    print(f"AI hand: {render_hand(game.hands[cfr_seat])}")
    print(f"Your hand: {render_hand(game.hands[human_seat])}")
    u = game.utility(human_seat)
    print("*** YOU WIN ***" if u > 0 else ("*** AI WINS ***" if u < 0 else "*** TIE ***"))
```

## 常见疑问 FAQ

### Q1: 为什么 game.py 把"同时出牌"建模成"序列出牌+隐藏信息"？

CFR 的博弈树天然是序列结构——每个节点只有一个当前玩家。"同时出牌"违反这个结构。

OpenSpiel 的标准做法：让 P1 先选、把选择存进 state 但**不更新 P2 的 observation**，然后让 P2 在不知道 P1 选了啥的前提下选。两人都选完后揭示。这样**博弈树是序列的**，**信息上仍是同时**。

实现见 `game.py:114-127`。

### Q2: 为什么用 `defaultdict` 而不是普通 dict？

CFR 训练中频繁出现"第一次见到某个 info set"。普通 dict 要写：

```python
if info_set not in self._regrets:
    self._regrets[info_set] = {}
if action not in self._regrets[info_set]:
    self._regrets[info_set][action] = 0.0
self._regrets[info_set][action] += delta
```

defaultdict 一行：

```python
self._regrets[info_set][action] += delta
```

代价：内存稍多（每次访问 key 都创建条目），读操作要小心用 `.get()`。

### Q3: 为什么 CFR 用「累计 regret」而不是直接梯度下降？

数学上证明：**遵循 regret matching 的策略序列的累计平均会收敛到 Nash 均衡**（在 zero-sum 博弈下）。这是 Hart & Mas-Colell 2000 年的结果。梯度下降在多智能体设置下不一定收敛（会有循环）。

直观理解：regret 累加是有"长期记忆"的——某个动作累计亏多了就一直被压低，单次的噪声不会让策略剧烈震荡。

### Q4: 为什么训练时用 `get_strategy`，推理时用 `average_strategy`？

`get_strategy` = regret matching 算出的**当前迭代**策略。它会一直震荡（在迭代 t 和 t+1 可能完全不同）。

`average_strategy` = 历史所有迭代策略的**累计平均**。CFR 的数学保证是：这个平均收敛到 Nash，而不是任何单一迭代的当前策略。

混用是典型 bug：用 `average_strategy` 训练会让收敛极慢甚至不收敛；用 `get_strategy` 推理会得到一个剧烈震荡的弱策略。

### Q5: 为什么 Kuhn 用 External Sampling，主游戏用 Outcome Sampling？

- **ES**：在 traverser 节点枚举所有动作。每 iter 时间 ∝ branching^depth。Kuhn 是 2 动作 × 深度 3 = 8 节点，极快。
- **OS**：只采样一条路径。每 iter 时间 ∝ depth。主游戏 32 动作 × 深度 12，ES 跑不动；OS 可行但有 importance sampling 方差。

详见 `mccfr.py` 顶部注释和诊断报告 §4。

### Q6: `seed` 是干啥的？为什么处处都传？

`random.Random(seed)` 创建一个**确定性的**随机数生成器。同一个 seed 总是给同一个数列。

意义：
- 训练可复现：跑 1000 iter，第二次再跑结果完全一样
- 测试稳定：随机测试 `test_xxx(seed=0)` 永远走相同路径
- 评估公平：`play_match(a, b, seed=42)` 让 a 和 b 跑相同 500 局

如果用全局 `random.random()` 就没法保证。

### Q7: 训练为什么要交替 traverser？

CFR 学每个玩家的策略时，**假设对手按当前 σ 玩**。如果只学 P0：
1. iter 1：P0 学 → σ_0 更新；σ_1 还是初始 uniform
2. iter 2：P0 学针对 uniform 对手的策略 → 收敛到针对 uniform 的最优，不是 Nash

交替学：iter 偶数学 P0、iter 奇数学 P1，**两个 σ 同时演化**，互相追赶 → 收敛到 Nash。

### Q8: 为什么训练完用 1.8GB 这么大？

`cfr_a0c986b_1000000.pkl` 1.8GB 装了：
- `_regrets`：4.36M info sets × 平均 ~5 actions × 一个 float = ~1.7 亿条 (key, action, float)
- `_cumulative_strategy`：同上规模 = 另一份 1.7 亿条
- 加上 dict + string key 的 Python 开销

每个 info set key 是 `repr(tuple)` 出来的长字符串（~150 字节），4.36M × 150B × 2 = 1.3GB 仅 key。这就是为什么诊断报告说要做 info set 抽象——不光为了训练收敛，也为了文件大小。

### Q9: 训练没收敛我现在该咋办？

参见 `Improvement/训练未收敛诊断.md` §6 的修复方向。最高 ROI 是改 `info_set.py` 去掉 redraw_history 这类沉没历史 + 把本轮 redraw 信息压成 count，把 info set 数从 4M 降到 ~10⁵ 级。

## 词汇表

| 术语 | 含义 |
|---|---|
| **CFR** | Counterfactual Regret Minimization。一类不完美信息博弈的迭代学习算法。 |
| **MCCFR** | Monte Carlo CFR。CFR 的采样版本（External / Outcome Sampling）。 |
| **info set / 信息集** | 同一个玩家"看不出区别"的所有真实状态的集合。策略必须以 info set 为单位（不能区分对手暗牌）。 |
| **Observation** | 一个玩家在某决策点看到的所有可见信息。我们的 dataclass `Observation`。 |
| **info_set_key** | `encode_info_set(observation)` 输出的字符串，CFR 表的 key。 |
| **regret** | 累计"早知道我就选 a 该多好"的量。正 regret 推动策略多选 a，负 regret 压制。 |
| **regret matching** | 给定 regret 算策略：`P(a) ∝ max(0, regret(a))`。 |
| **average strategy** | 所有迭代的策略累加归一化。**这是收敛到 Nash 的量。** |
| **Nash 均衡** | 双方都对对手的策略最佳响应、谁也不能单方面改善的策略组合。 |
| **exploitability** | 当前策略离 Nash 多远的量化指标。`BR_0 + BR_1` 之和。 |
| **BR / best response** | 给定对手策略，我能拿到的最大期望回报对应的策略。 |
| **traverser** | CFR 算法本 iter 在学习的玩家。 |
| **bitmask** | 用二进制位表示选了哪几个东西。REDRAW 阶段的 action 0-31。 |
| **importance sampling** | 用采样路径估计期望时的方差矫正。OS 必须用 IS。 |
| **fold dominance / 弱占优** | 在此博弈下，"play+STOP" 弱占优于 fold。详见 §4.5.5。 |
| **pickle** | Python 对象序列化机制。我们用它存 RegretTable。 |
| **defaultdict** | 字典变种，访问不存在的 key 自动创建默认值。 |
| **dataclass** | Python 装饰器，自动生成 `__init__`/`__eq__` 等。我们的 Observation 用了。 |
