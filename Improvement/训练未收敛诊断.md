# MCCFR 训练未收敛诊断报告

**日期**：2026-05-24
**Checkpoint**：`cfr/checkpoints/cfr_a0c986b_1000000.pkl`（10⁶ iter, 4h 15min）
**结论**：算法实现正确，但**未达到可用的收敛水平**。原因是 *info set 空间过大 + Outcome Sampling 的 importance-sampling 方差爆炸* 双重叠加。需要重新设计 info set 抽象（详见 §5）才能让训练有意义。

---

## 1. 症状

`cfr/eval/play.py` 500 局 vs 5 个 rule baseline（详见 §4.5.5），**1M-iter checkpoint 与未训练相比基本没区别**：

| 对手 | Untrained (50 局) | Trained 1M (500 局) | Δ |
|---|---|---|---|
| `random` | -0.020 | +0.020 | +0.04（噪声） |
| **`always_call`** | -0.600 | **-0.640** | **-0.04（更差）** |
| **`tight`** | +0.120 | **-0.084** | **-0.20（更差）** |
| `loose` | -0.800 | -0.784 | +0.02（噪声） |
| `heuristic` | -0.580 | -0.584 | 0 |

vs `always_call` 仍是 -0.64：意味着训练后 CFR 仍以可观概率选择 fold——而 §4.5.5 已证明 fold 在此博弈中是弱占优动作，正确收敛的 average strategy 应该 P(fold)→0。

## 2. Sampled Exploitability 没有下降

`cfr/logs/train_a0c986b.csv`：

| iter | sampled_exploit |
|---|---|
| 10,000 | 1.855 |
| 100,000 | 1.745 |
| 500,000 | 1.760 |
| 1,000,000 | 1.795 |

整个训练过程中在 1.69–1.86 之间随机震荡，**没有任何下降趋势**。这本身可能被高方差估计噪声掩盖，但结合 §1 的下游胜率数据，定性结论一致：训练没收敛。

## 3. 根因：cum_strat 退化为 uniform

CFR 推理时使用的是 `average_strategy`（cumulative strategy 归一化），不是 `get_strategy`（regret matching）。我们 dump 1M checkpoint 的内部状态：

```
总 info sets:          4,362,334
多动作 info sets:      3,681,916   (84.4%)
其中 cum_strat 完全均匀: 3,429,472   (93.1%)   ← 致命
```

样例（任取一个 multi-action info set）：

```
regrets   = {0: +190464, 1: -190464}    ← 显著偏好 action 0
cum_strat = {0: 832.0,   1: 832.0}      ← 完全均匀
average   = {0: 0.5,     1: 0.5}        ← 等价于随机
get_strategy = {0: 1.0,  1: 0.0}        ← 当下迭代的纯策略（正确）
```

**`average_strategy` 永远是 uniform**，所以 CFRAgent 推理出来的策略就是 uniform 随机——与未训练完全等价。

`cum_strat` 的 sum 分布同样说明问题：

| 统计量 | 值 |
|---|---|
| Mean | 6.27 × 10⁵ |
| Median | **9.0** |
| Max | 6.49 × 10¹¹ |

中位数只有 9——意味着一半 info set 的累计权重等价于几次访问。极长尾的均值（10¹¹ 级最大值）来自 §4 描述的 IS 修正爆炸。

## 4. 机理：为什么会变成 uniform

### 4.1 OS-MCCFR 的累计策略更新公式

`cfr/agent/mccfr.py:144`：

```python
increment = {a: my_reach * sigma[a] / sample_reach for a in legal}
regret_table.update_cumulative_strategy(info_set, increment)
```

其中 `sample_reach` 是从根到当前节点采样路径的累积概率（importance sampling 修正）。

### 4.2 数值塌陷

游戏深度可达 ~12 层（3 轮 × 2 阶段 × 2 玩家），动作空间最多 32（redraw 5 位 bitmask）。OS 用 ε=0.6 探索：

```
sample_dist[a] ≥ ε/n = 0.6/32 ≈ 0.019
sample_reach 下界 ≈ 0.019^depth
对 depth=6: 0.019^6 ≈ 5 × 10⁻¹¹
```

所以 `1 / sample_reach` 可达 10¹⁰ 量级。

### 4.3 单次访问就吃满

- **首次访问**：regrets 全 0 → `sigma` 是 uniform `1/n`。
  `increment[a] = (1/n) / sample_reach` ≈ 10⁸–10¹⁰ ——**每个动作都加这么多**。
- **后续访问**：regrets 已分化，`sigma` 接近 pure on a\*。
  `increment[a*] = 1 / sample_reach` ≈ 10⁹，others = 0。
  但因为不同访问的 a\* 选择会在 ε-explore 下分散到几乎所有动作，整体上各动作累计相近。

**结果**：首次 uniform 访问 + 后续散布在所有动作上的访问 → cum_strat 永远是「全员近似平等」。

### 4.4 为什么访问次数这么少

游戏可达 info set 数随状态空间组合爆炸增长。1M iter × 平均轨迹长度 ~12 节点 ≈ 1200 万节点访问。但 info sets 总数 = 4.36M，导致**平均每个 info set 只被访问 ~3 次**。中位数访问次数为 1。

## 5. 这 **不是** 实现 bug，是 *scale-mismatch*

排查证据：

| 测试 | 结果 | 结论 |
|---|---|---|
| Kuhn + External Sampling 2k iter | cum_strat 显著非均匀 ✓ | RegretTable 实现正确 |
| Kuhn 端到端 exploitability | 收敛到接近 Nash ✓ | external_sampling 算法正确 |
| `get_strategy` 输出 | regret matching 正确返回 pure ✓ | regret matching 实现正确 |
| 单元测试 89/89 + 集成测试 14/14 | 全部通过 ✓ | 没有显式 bug |
| OS-MCCFR + PokerGame 5k iter | 12715 个重访问 info set 中 100% uniform | OS 在 PokerGame 上失效 |

所有组件都正确——只是 OS-MCCFR 处理不了当前的 info set 空间规模。

## 6. 三个修复方向（按 ROI 排序）

### 6.1 减小 info set 抽象（**高 ROI**）

> **勘误（2026-06-02）**：本节「删 redraw 历史可降到几十万级」的估计**被实测推翻**——用 1M checkpoint 全量 key 投影，删两个 redraw 历史仅 −2%，连本轮细节一起删也只 −4%（历史几乎是其他字段的函数）。真正有效的是**手牌折叠 + 对手明牌分桶**。修正后的方案与实测数据见 `收敛优化设计.md` §2。

`cfr/agent/info_set.py` 当前 21 个字段，其中**高基数维度**（每个候选）：

| 字段 | 估计基数 | 是否真的需要 |
|---|---|---|
| `my_redraw_history` | 32^3 = 32K | ⚠️ 已用过即沉没，仅决策当前轮无影响 |
| `opp_redraw_history` | (5个数字)^3 = 125 | 同上 |
| `my_redraw_actions_this_round` | 32^k | ⚠️ 详细到每个 bitmask，可压缩为「本轮已抽张数」 |
| `opp_redraw_counts_this_round` | k! | 同上 |
| `opp_face_up` | 13×2 排列 | 已抽象到 suit-aligned，但 cardinality 仍高 |

**预期收益**：去掉 redraw history（沉没成本）、把本轮 redraw 信息压成单个 count → info sets 数可从 4M 降到几十万级。每个 info set 平均访问次数 ×10。

**代价**：改 info_set.py ~50 行 + 重训 ~4h。但**破坏现有 checkpoint**（key 编码变了）。

### 6.2 换 External Sampling

OS 的 IS 修正是噪声来源。External Sampling 在 traverser 节点枚举所有动作，没有 IS 修正：

- 每 iter 时间 × ~32（因为不再单一采样）
- 但每 iter 信息量也 ×32
- 整体 wall time 估计 ×3–5
- **预计**：1M iter under ES ≈ 12–20h，可能仍不足以覆盖 4M info sets

不建议单独走这条路，必须配合 6.1。

### 6.3 Linear CFR 加权

把 regret 更新和 cum_strat 更新都乘以 iteration index t：

```python
# 原：update_regret(info_set, a, delta)
# 新：update_regret(info_set, a, t * delta)
# 原：update_cumulative_strategy(info_set, sigma)
# 新：update_cumulative_strategy(info_set, {a: t * sigma[a] for a in legal})
```

后期 iter 权重压制前期 uniform 噪声。**单独用**对 scale 问题无效，但配合 6.1 可加速收敛。

### 推荐组合

**Step 1**: 6.1（info set 抽象瘦身）单独足以解决问题。
**Step 2**: 如果 Step 1 后仍不够干净，叠加 6.3（Linear CFR）。
**Step 3**: 6.2 是最后兜底，因为时间成本极高。

## 8. 验证脚本（任意时刻重跑）

```python
# vs rule panel 评测（500 局 / 对手）
from cfr.eval.cfr_agent import CFRAgent
from cfr.eval.play import play_match
from cfr.eval.rule_agents import (
    RandomAgent, AlwaysCallAgent, TightAgent, LooseAgent, HeuristicAgent
)

cfr = CFRAgent.from_checkpoint("cfr/checkpoints/cfr_a0c986b_1000000.pkl")  # 2026-07-02 起 API 无 seed 参数
for name, opp in [
    ("random",      RandomAgent(seed=1)),
    ("always_call", AlwaysCallAgent()),
    ("tight",       TightAgent()),
    ("loose",       LooseAgent()),
    ("heuristic",   HeuristicAgent()),
]:
    r = play_match(cfr, opp, num_games=500, seed=42)
    print(f"{name:<14} a_avg_u={r['a_avg_utility']:+.3f}  "
          f"W-T-L: {r['a_wins']}-{r['ties']}-{r['b_wins']}")
```

```python
# cum_strat 均匀比例检验（确认未收敛）
from cfr.train.checkpoint import load_checkpoint
table = load_checkpoint("cfr/checkpoints/cfr_a0c986b_1000000.pkl")["regret_table"]
uniform = total = 0
for k, cs in table._cumulative_strategy.items():
    if len(cs) <= 1: continue
    total += 1
    vs = list(cs.values())
    if max(vs) - min(vs) < 1e-3: uniform += 1
print(f"Uniform cum_strat: {uniform}/{total} = {100*uniform/total:.1f}%")
# 期望：训练正常时 < 30%；当前 = 93.1%
```
