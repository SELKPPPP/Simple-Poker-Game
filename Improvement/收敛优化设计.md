# CFR 收敛优化设计

**日期**：2026-06-02
**前置文档**：[训练未收敛诊断.md](训练未收敛诊断.md)
**目标**：重新设计 info-set 抽象 + 加 Linear CFR，让 MCCFR 在 PokerGame 上**真正收敛**（重训后能稳定打赢 rule baselines），而非停留在均匀随机。
**范围**：全部改动限制在 `cfr/`（`info_set.py`、`mccfr.py`，可能 `trainer` 传迭代序号）。不碰 Backend/Frontend/DB/原 `model/`。

---

## 1. 背景：为什么要重做抽象

诊断报告（§3）已确认 1M-iter checkpoint 失败：4,362,334 个 info set，93.1% 的多动作 info set 的 `cumulative_strategy` 退化为均匀，导致推理用的 `average_strategy` 等价于随机。

根因是 **scale-mismatch**：info set 太多（中位访问次数 = 1），叠加 Outcome Sampling 的 importance-sampling 方差爆炸（§4）。

---

## 2. 关键实测：推翻原诊断的 §6.1

诊断 §6.1 推荐"砍掉 redraw 历史字段"来把 4.36M 降到几十万。**用现有 checkpoint 的全部 key 实测后，这个判断是错的。**

### 2.2 删字段的真实收益（投影现有 key 计算精确联合基数）

| 配置 | info_sets | 降幅 |
|---|---|---|
| baseline（全 21 字段） | 4,362,334 | — |
| 删两个 redraw 历史(19,20) | 4,276,772 | **−2%** |
| + 删本轮 redraw 细节(12,13) | 4,178,603 | **−4%** |
| + 分桶 opp_face_up | 2,036,733 | −53% |

**结论**：redraw 历史虽然单字段基数高，但**几乎是其他字段的函数**（抽牌历史决定当前手牌，手牌已被编码），删掉几乎不删行。删历史只能省内存、清理冗余，**解决不了 scale 问题**。

### 2.3 真正的爆炸来源 = 三个子空间的联合乘积

| 子空间 | distinct |
|---|---|
| 手牌表示 `{rank,top,suited,straight,draw}` (0-4) | 6,228 |
| `opp_face_up` (5) | 2,938 |
| 资源+比分+阶段 (6,7,8,9,10,11,16,17,18) | 1,927 |

### 2.4 分桶能达到的目标点（实测）

| 减后抽象 | info_sets | 中位访问/iset @1M iter |
|---|---|---|
| hand→{rank,draw} + 分桶 opp_face_up + 删历史 | 99,807 | ~10 |
| **+ 粗 rank 桶 + remaining_redraws 截≤4** | **27,671** | **~36** |

**选定操作点：~2.7 万 info sets**（激进档）。理由：中位 ~36 次访问足以让 CFR 真正收敛、可见地证明 uniform% 下降。课程项目里"收敛的粗略 agent"胜过"未收敛的精细 agent"。代价是丢掉 kicker / mask 位置信息，玩法较粗。

## 3. 设计

### 3.1 成功标准（验证目标）

1. `uniform cum_strat 比例` 从 93% 降到 **<30%**
2. sampled-exploit 出现**下降趋势**（不再在 1.69–1.86 震荡）
3. 对 `always_call` 从 −0.64 **转正**（即 P(fold)→0，符合 §4.5.5 fold 弱占优分析）

### 3.2 第 1 部分：重写 `info_set.py` 的 `encode_info_set`

目标 ~3 万 info sets。保留/删除/分桶如下：

**保留（精确）：**
- `hand_rank`、`draw_type`
- `phase`、`round_num`
- `my_round_wins`、`opp_round_wins`
- `my_remaining_redraws`（**保持精确，见 §3.4 合法动作约束**）

**分桶：**
- `opp_face_up` → `(对齐我主花色的张数, max_rank // 4)`，替代精确的 sorted `(rank, aligned)` 元组
- `opp_remaining_redraws` → `min(opp_rem, 4)`（对手预算**不影响我的**合法动作集，截断安全；见 §3.4）

实测联合基数（投影现有 4.36M key）：此抽象 = **35,331 info sets**，@1M iter 中位 ~28 次访问/iset。备选更粗档 T3（opp 仅留对齐张数）= 18,245。

**删除（沉没成本 / 冗余 / 低价值）：**
- `top_card`、`suited_mask`、`straight_mask`（折叠进 hand_rank+draw_type）
- `my_redraw_actions_this_round`、`opp_redraw_counts_this_round`（本轮 redraw 细节）
- `my_redraw_done`（恒为 1，无信息）、`opp_redraw_done`
- `opp_fold_this_round`
- `my_fold_history`、`opp_fold_history`
- `my_redraw_history`、`opp_redraw_history`

具体桶边界（如 rank 桶用 `//4` 还是其他、opp 是否再加一维）在实现阶段用 §6 的投影工具锁定到 ~3 万。

### 3.3 第 2 部分：在 `mccfr.py` 加 Linear CFR

regret 增量和 cumulative-strategy 增量都乘以迭代序号 `t`：

```python
# regret 更新：update_regret(info_set, a, t * delta)
# cum-strat 更新：update_cumulative_strategy(info_set, {a: t * sigma[a] for a in legal})
```

作用：后期已分化的访问权重压过早期被 IS 放大的均匀访问，直接对抗诊断 §4.3 的退化机制。需要 trainer 把当前迭代序号 `t` 传进采样函数。

`ε`（当前 0.6）作为短训阶段的备用可调项——若分桶+Linear CFR 仍不够干净，再降低 `ε` 以缩小 `1/sample_reach` 方差。

### 3.4 合法动作一致性约束（正确性）

CFR 抽象的硬约束：**共享同一个 info-set key 的所有底层状态，必须有完全相同的合法动作集**，否则学到的 regret 会在不同动作可用性的状态间被混淆。

- `phase` 保留 → FOLD(2 动作) 与 REDRAW(≤32 动作) 永不合并 ✓
- REDRAW 的合法动作 = popcount ≤ **我自己**预算的所有 bitmask + STOP。所以 `my_remaining_redraws` **不能截断**（截 4 会把我的预算 4 和 7 合并 → 不同合法集），保持精确。
- 但 `opp_remaining_redraws` 截断**安全**：对手预算不进入我的合法动作判定，只是观测信息，可分桶（§3.2 用 `min(opp_rem,4)`）。

### 3.5 第 3 部分：验证流程

```
短训 50–100K iter
  └─ 检查闸门：uniform cum_strat % < 30%  且  exploit 有下降趋势
       ├─ 通过 → 全量 1M 重训
       │           └─ 对 5 个 rule baseline 评测（§3.1 成功标准）
       └─ 不通过 → 降 ε / 调桶边界，重跑短训
```

会产生**新 checkpoint**；旧的 1M checkpoint 作废（key 编码已变，不兼容）。

## 6. 复核工具（实现阶段锁定桶边界用）

投影脚本思路（读现有 checkpoint 的 key，按候选字段子集计 distinct）：

```python
import ast
from cfr.train.checkpoint import load_checkpoint
table = load_checkpoint("cfr/checkpoints/cfr_a0c986b_1000000.pkl")["regret_table"]
tups = [ast.literal_eval(k) for k in table._cumulative_strategy.keys()]

def count(keep, tf=None):
    s = set()
    for t in tups:
        if tf: t = tf(t)
        s.add(tuple(t[i] for i in keep))
    return len(s)
# 用不同 keep 子集 / transform 逼近 ~3 万
```

> 注：此投影是在**旧抽象的 key 上**逼近，仅用于估计联合基数量级。新 `encode_info_set` 写好后应在真实 rollout 上重新统计 info-set 数确认。
