# 第一部分：博弈论基础

## 1.1 什么是博弈（Game）

在数学里，"博弈"就是**多方理性参与者按规则做决策、各自有不同目标**的场景。三要素：

- **玩家**（Players）：例如 P1 和 P2
- **动作**（Actions）：每个玩家在某一时刻能做什么（出牌、加注、弃牌……）
- **收益**（Payoff/Utility）：游戏结束时每个玩家得到什么（赢 1 分、输 -1 分）

我们这个项目是 **2 人零和博弈**：P1 得 1 分必然 P2 得 -1 分，反之亦然。零和意味着**双方利益完全对立**，所以 Nash 均衡是有意义的。

## 1.2 完美信息 vs 不完美信息（核心！）

| 类型 | 例子 | 特征 |
|---|---|---|
| 完美信息（perfect info） | 国际象棋、围棋 | 双方看到的状态完全相同 |
| 不完美信息（imperfect info） | 扑克、桥牌、外交 | 各自有「私有信息」（手牌） |

我们最早的项目是完美信息：双方手牌全部 5 张都摊在桌上。这次升级到不完美信息：**2 张 hole（藏起来）+ 3 张 face-up（亮出来）**。

**为什么这个区别这么重要？** 因为算法选型完全取决于它：
- 完美信息 → 用 minimax / Q-learning / AlphaZero 都行
- 不完美信息 → 必须用 CFR 家族，Q-learning 在理论上就不适用（后面 §2.4 会讲）

## 1.3 纳什均衡（Nash Equilibrium）

**直觉**：一组策略，所有玩家都没动力单方面改变自己的策略，因为单改只会让自己更差或一样。

**两人零和博弈的特殊性质**：Nash 均衡策略**不可被剥削**。换句话说，即使对手知道你的策略，也无法稳定赢你。

我们训 CFR 的目标就是逼近这个 Nash 策略 —— 这样 agent 打任何对手（包括真人）都不会被系统性剥削。

## 1.4 混合策略（Mixed Strategy）

**纯策略**：在某局面下，"我永远选 action A"。
**混合策略**：在某局面下，"我 70% 选 A，30% 选 B"，用骰子决定。

**为什么 poker 必须用混合策略？** 假设你在 bluff 位置永远选 bluff，对手只要发现就永远 call → 你被剥削。所以最优策略必然是「以一定概率 bluff，以一定概率 fold」的混合。

CFR 输出的就是混合策略：每个 info set 一个 action 概率分布。

# 第二部分：强化学习（RL）基础

## 2.1 什么是 RL

RL 解决的是「**反复试错学最优行为**」问题。要素：

- **环境**（environment）：游戏 / 物理世界
- **agent**：会做决策的家伙
- **状态**（state）：当前局面
- **动作**（action）：agent 能做什么
- **奖励**（reward）：环境对 agent 的反馈

循环：`观察 state → 选 action → 环境给 reward + 新 state → 学习 → 下一步`。

## 2.2 MDP（Markov Decision Process）

RL 的标准数学框架。关键假设：**马尔可夫性** —— 下一步的状态和奖励只取决于当前状态和动作，跟历史无关。

象棋满足 MDP：当前棋盘 + 我下一步走法 → 完全决定了对方面临的局面。

## 2.3 Q-learning 一句话总结

学一个表 `Q[state, action] = 期望长期奖励`。每次更新：

```
Q[s, a] ← Q[s, a] + α × (reward + γ × max(Q[s', a']) - Q[s, a])
```

行动时：在状态 s 选 `argmax_a Q[s, a]`。

**原项目用的就是这个**：`model/poker_qlearning.py`，q-table 大约 10^4-10^5 entries。

## 2.4 POMDP——Q-learning 为什么在 poker 失效

POMDP = **Partially Observable** MDP = 不完美信息 MDP。

引入隐藏手牌后，agent 看到的「observation」**不再是真正的 state**。同一个 observation 可能对应对手不同的 hole cards，对应不同的最优动作。

更要命的是：

1. **不存在纯策略最优解**。如前述，poker 最优策略是混合的，但 Q-learning 输出的是 `argmax` —— 永远纯策略。
2. **马尔可夫性被打破**。当前 observation 不足以预测未来，因为「对方记得我之前的下注」会影响他未来的决策。
3. **`max` 操作引入乐观偏差**。Q-learning 假设对手会让你拿到 max，poker 里对手会想办法让你拿到 min。

**所以我们换 CFR**。

# 第三部分：CFR 家族（项目核心）

## 3.1 CFR 在干什么（直觉版）

想象一个无限自我对弈的过程：

1. 我跟"我自己"打了 10 万局
2. 每一局结束后，复盘每个决策点：「如果当时我选另一个动作，结果会更好吗？」
3. 如果某个动作经常事后看更好 → 下次在这种局面下增加它的出现概率
4. 重复 10 万次 → 策略收敛到 Nash 均衡

**关键词**：
- 「事后觉得另一个动作更好」 → **regret**（后悔值）
- 「根据 regret 调整概率」 → **regret matching**
- 「无限对弈后的平均策略」 → **average strategy**（这才是收敛到 Nash 的东西，不是当前策略！）

## 3.2 什么是「后悔值」（Counterfactual Regret）

在一个 info set $I$ 下，对动作 $a$ 的「counterfactual regret」定义为：

$$
R(I, a) = \sum_{\text{所有 history}} (\text{如果我在 I 永远选 a，能多赚多少})
$$

**简化版直觉**：「我当时如果一直选 a，比我实际策略好多少？」

- $R(I, a) > 0$：选 a 更好，**早该多选 a**
- $R(I, a) < 0$：选 a 更差，**少选 a 是对的**

## 3.3 Regret Matching 算法

下次到达 info set $I$，每个 action 的概率：

$$
P(a | I) = \frac{\max(0, R(I, a))}{\sum_{a'} \max(0, R(I, a'))}
$$

**例子**：3 个 action 的 regret 是 [+5, -3, +2]
- clip 到 0：[5, 0, 2]
- 归一化：[5/7, 0, 2/7] ≈ [71%, 0%, 29%]

所以 agent 会以 71% 概率选 action 0，0% 选 action 1，29% 选 action 2。

**如果所有 regret ≤ 0**：均匀概率（所有 action 都没价值，那就随机）。

## 3.4 为什么"平均策略"收敛到 Nash（不是当前策略！）

**反直觉但极其重要的点**：迭代过程中，当前策略会**剧烈震荡**（这次偏向 A，下次偏向 B），不收敛。

但**平均策略**（所有迭代的 average）会收敛到 Nash 均衡。

直觉解释：Nash 均衡本质上是**混合**策略。如果直接看某一次迭代的策略，是不平衡的（regret 还在推动它震荡）；只有把所有迭代平均起来，才能"撑住" Nash 那种正好谁也无法剥削的微妙概率。

**实操影响**：训练时要维护两个表：
- `regret_table`：用来选下一步策略的（regret matching）
- `strategy_sum_table`：累加每次的策略，最后**除以迭代次数**得到平均策略
- **部署/对战时用的是 average strategy，不是当前 regret table 给出的策略**

## 3.5 Vanilla CFR（完整版）

最朴素的 CFR：每次迭代**遍历完整博弈树**，更新所有 info set 的 regret。

**问题**：博弈树太大。我们这个游戏估算 $10^5 - 10^6$ info sets，每个 info set 又有多种到达路径，完整遍历一次太慢。

## 3.6 MCCFR（Monte Carlo CFR）

只**采样**一部分博弈树而不是全部遍历。三种主要变体：

| 变体 | 怎么采样 | 特点 |
|---|---|---|
| **Outcome Sampling** | 每次只走一条到 terminal 的路径 | 方差大、收敛慢，但每步快 |
| **External Sampling** | 自己所有动作都遍历，对手 + chance 只采一个 | **方差小、收敛稳**，单步稍慢 |
| **Chance Sampling** | 只对 chance node 采样 | 介于上面两者之间 |

**我们用 External Sampling**：在 self-play 中两个玩家轮流当"自己"。

## 3.7 External Sampling MCCFR（我们选的算法）

伪代码：

```
ExternalSampling(node, traverser):
    if node is terminal:
        return utility(traverser)
    if node is chance:
        sample one outcome, recurse
    if current player == traverser:
        # 遍历所有动作
        for each action a:
            v[a] = ExternalSampling(node.apply(a), traverser)
        v_node = sum(strategy[a] * v[a])
        for each action a:
            regret[I, a] += v[a] - v_node
        return v_node
    else:
        # 只采一个对手动作
        a = sample from opponent strategy
        return ExternalSampling(node.apply(a), traverser)
```

每次迭代分两次：一次 traverser=0、一次 traverser=1。

**这就是我们 Phase 2 要实现的核心**。

## 3.7.5 Outcome Sampling MCCFR（Phase 3 PokerGame 用）

ES 在 Kuhn 上没问题（action space = 2，每个 traverser 节点枚举 2 个分支），但在主游戏 PokerGame 的 REDRAW 阶段挂掉：满 budget 时 32 个合法 action，traverser 要全部枚举，加上 redraw 可迭代多次 + 3 个 round → 分支因子 32^k 量级，一个 iter 30s 都跑不完（Phase 3 实测）。

**Outcome Sampling (OS)** 的差别：traverser 也只采样一个 action（带 ε-exploration 保证所有 action 都能被探到），不枚举。代价是单 iter 信息量少（只更新沿采样轨迹的 info set），收敛更慢。但每 iter 时间从指数级降到 **O(树深度)**，总时间反而短得多。Pluribus / Libratus 用的也是 OS 路线。

### 关键 IS（importance sampling）修正

采样不是按真实 σ，而是按 σ' = (1-ε)σ + ε/n（ε-exploration 后的分布）。要让估计无偏，必须把 IS 比 σ/σ' 累乘到 utility 上。OpenSpiel python 的标准公式（也是 Phase 3 实现的版本）：

```
每个节点收到 child_value，先除以 sample_dist[sampled]：
    sampled_corrected = child_value / sample_dist[sampled_action]
value_estimate（往上传）= σ[sampled] × sampled_corrected

regret 更新（仅在 traverser 自己节点）：
    cf_value = value_estimate × opp_reach / sample_reach
    cf_action_value[sampled] = sampled_corrected × opp_reach / sample_reach
    cf_action_value[非 sampled] = 0   # baseline = 0
    regret[a] += cf_action_value[a] - cf_value

cumul strategy 更新：
    S[I][a] += my_reach × σ[a] / sample_reach
```

**实现踩坑**：少了 `/sample_dist[sampled]` 那一步 IS correction → 收敛卡在 exploit ≈ 0.33。Phase 3 改了 3 版才对（详见 CHANGELOG 2026-05-22）。

### Kuhn 上 ES vs OS 对比（实测）

| | ES (Phase 2) | OS (Phase 3) |
|---|---|---|
| 收敛速度 | 10⁵ iter → exploit ≈ 0.003 | 10⁶ iter → exploit ≈ 0.01 |
| 单 iter 耗时 | ~50μs（树深 ≤ 3 全枚举） | ~30μs（树深 ≤ 3 采样） |
| 主游戏可用？ | 不行（32^k 爆炸） | 可以（~3ms/iter） |

## 3.8 Deep CFR——为什么本项目不用

Deep CFR = CFR + 神经网络代替表。

**优点**：当 info set 数量大到 $10^9$ 以上、表存不下时唯一选择。
**缺点**：训练复杂、调参 vs MCCFR 表格难得多、可解释性差、要验证正确性极难。

**为什么本项目不用**：估算我们的 info set 数量 $10^5 - 10^6$，表完全可以塞进内存。表格 MCCFR 还有个巨大优势：**可以直接 print regret 表 debug**，能在 Kuhn Poker 这种 toy 游戏上**验证收敛到已知 Nash**（金标准）。

# 第四部分：我们游戏的规则与设计

## 4.1 完整规则（v3 当前生效）

**总体**：BO3（best of 3 rounds），两人，先赢 2 round 的获胜。

**每 round 流程**：
```
1. DEAL: 双方各发 5 张牌（其中 2 张 hole 藏，3 张 face-up 亮）
2. FOLD phase: 双方同时选 play 或 fold
   - 任一方 fold → 直接判定 round 结果，跳过 redraw（保留全部 redraw 配额）
   - 双方都 fold → push
   - 双方都 play → 进入 REDRAW phase
3. REDRAW phase（迭代）:
   loop until 双方都 STOP:
     - 双方同时选 action ∈ {0..31}
     - action == 0 表示 STOP（本 round 不再换）
     - action ∈ 1..31 是 5-bit bitmask，第 i 位 = 1 表示换第 i 张
     - 每次换牌消耗对应数量的 redraw 配额
     - 配额耗尽 → 强制 STOP
4. SHOWDOWN: 比较手牌大小，赢的得 1 round
```

**资源**：
- 整局共享 7 次 redraw 配额（不是每 round 7 次）
- 这就引入跨 round 资源博弈

## 4.2 牌型大小（标准 poker rankings）

从大到小：
1. Royal Flush（A-K-Q-J-10 同花）
2. Straight Flush（同花顺）
3. Four of a Kind（4 条）
4. Full House（葫芦 / 3+2）
5. Flush（同花）
6. Straight（顺子）
7. Three of a Kind（3 条）
8. Two Pair（两对）
9. One Pair（一对）
10. High Card（高牌）

实现在 `cfr/env/poker_rules.py`。

## 4.3 Information Set（信息集）

**核心定义**：一组**对玩家不可区分的 state**。

在我们游戏里，info set 包含：
- 自己 5 张手牌
- 对方 3 张 face-up
- 双方剩余 redraw 配额
- 双方过往 round 的 fold history、redraw history
- 当前 phase、round 数

**不包含**（也不可能包含）：
- 对方的 2 张 hole（你看不到）
- 对方当前 iter 还没 commit 的 pending action

**为什么这个定义这么关键**：CFR 的策略表是用 info set 当 key 的。如果两个不同的 state 应该映射到同一个 info set（因为你区分不了它们），你必须保证算法用同一个 key 索引它们，否则等同于"作弊"。

**Phase 1 的任务**就是给 `Observation` 设计一个 **canonical encoding**：把它变成一个字符串 key。

**关键性质要求**：
- **同一玩家、看起来相同的两个 state** → 同一个 key
- **等价手牌**（如 ♠A♥K 和 ♥A♠K 在没有花色相关组合时）→ 同一个 key（否则状态空间炸掉）
- **确定性**：同一个 observation 永远 hash 到同一个 key

## 4.4 严格被支配（Strictly Dominated）—— 设计 game rules 的核心检查

**定义**：如果某 action a 在**所有可能的对手策略下**，都比 action b 差，则 b **严格支配** a。

理性 agent 永远不会选被支配的 action。所以如果你的规则里有被支配 action，CFR 会学出 `P(被支配 action) = 0`，等于没加这个 action。

**这是 v1→v2→v3 三次推翻 Phase 0 的核心教训**。

## 4.5 为什么 fold 要在 redraw 之前（v2 改动）

**原 v1 设计**：DEAL → REDRAW → FOLD → SHOWDOWN

**问题**：fold 在 redraw 之后。这时你已经花完了想花的 redraw，fold 不省任何资源；而 show 则有可能赢。所以 **show 严格支配 fold** → CFR 学出 `P(fold) = 0`。

**v2 修正**：DEAL → FOLD → REDRAW → SHOWDOWN

现在 fold 真有经济价值：保留全部 7 次 redraw 配额给后续 round。这就让 fold 在某些场景下（手牌烂、还有 2 round 要打）**严格优于** show。

## 4.5.5 已知设计冗余：fold 仍是弱占优（Phase 3 发现）

**§4.5 的 v2 修正实际未彻底解决支配问题**。Phase 3 训练设施完工后，重新审查游戏树时发现：

**关键事实**：REDRAW phase 的 STOP 动作（action=0）`bin(0).count('1')=0`，**不消耗任何 redraw 预算**（见 `game.py:175`）。

所以"fold"和"play+STOP"在预算消耗上**完全一致**（都不耗）。两者结果对比：

| 对手动作 | 你 fold | 你 play+STOP |
|---|---|---|
| 对手 fold | push (**0**) | 你赢 (**+1**) ← play 严格更好 |
| 对手 play | 你输 (**-1**) | 摊牌（−1 / 0 / +1） ← play 弱更好 |

差值：

$$\text{play+STOP} - \text{fold} = P(\text{opp fold}) \cdot 1 + P(\text{opp play}) \cdot (E[\text{showdown}] + 1) \geq 0$$

只要 P(对手 fold) > 0 或 P(摊牌不输) > 0（底牌随机几乎必然成立），fold 就严格劣。

**这意味着 v2 的"fold 保留预算"理由是错的**——play+STOP 也保留预算且只多不少。fold 本质上是 game design 冗余的。

### 为什么不修

修法的常规思路是：
- **加 ante 机制**：每局两边各下 1 注，fold 立即输 ante、play 输则输 ≥ ante。这就接近真扑克，但要改 game.py 接口、observation、info_set encoding、所有测试。**改动放射半径过大**。
- **play 加成本**：选 play 扣 1 redraw 预算。**违背 v3 plan §1"游戏定义稳定"原则**。

**v3 plan 的选择**：**保留 fold 作为模型动作空间完备性**——它存在但 CFR 会自然学到 `P(fold) → 0`。

### 对训练 / 评估的含义

1. **可验证的训练指标**：训练充分后，FOLD phase 的 info sets 上 `average_strategy` 的 fold 概率应该集中在 0 附近。这是 OS-MCCFR 收敛的一个 sanity check：如果某个 info set 还在 fold > 5%，说明该处的 reach probability 太低（采样不够）。

2. **Phase 4 rule panel 设计的关键洞察**：
   - **Tight agent**（弱牌就 fold）会被 CFR 屠杀——因为 CFR 学到对手 fold 倾向就 play+STOP 偷局
   - vs Tight 的胜率会非常高（≥ 70%）——这是验证 CFR 学到了"对手 fold 时永远 play"的核心指标
   - **Loose / Heuristic 才是真正的对手**（它们不会无脑 fold）

3. **Sampled BR 的间接验证**：BR 应该收敛到"在 FOLD phase 永远 play"。如果采样 BR 在 FOLD phase 还在折，说明 K-rollout 数太少。

## 4.5.6 1M-iter 训练未收敛（2026-05-24 实测）

10⁶ iter 训练完成后实测 vs rule panel，**与未训练几乎无差**，最差 vs `always_call` 平均效用 -0.640（按 §4.5.5 训练正常时应 ≥ +0.5）。

**根因**（详细诊断见 `Improvement/训练未收敛诊断.md`）：
- 4.36M info sets / 1M iter ≈ 平均 3 次访问，中位数 = 1 次
- OS-MCCFR 的 IS 修正 `1/sample_reach` 在 ε=0.6 + 深度 6 下可达 10¹⁰ 量级
- 首次访问时 regrets=0 → sigma=uniform → 单次 uniform increment 主宰 cum_strat
- **93.1% 多动作 info set 的 cum_strat 完全均匀** → `average_strategy` 退化为 uniform

**算法实现没 bug**（Kuhn + external_sampling 验证收敛），是 *info set 抽象规模 × OS 方差* 的 scale-mismatch。

**修复路径**（未实施，按用户决策保留现状作为诊断 artifact）：
- A. 削减 `info_set.py` 高基数维度（redraw_history 等沉没历史） — 最高 ROI
- B. 换 External Sampling — 时间成本高
- C. Linear CFR 加权 — 配合 A 用

> **后续（2026-07-02）：已修复。** 注意路径 A 的原始表述被实测部分推翻——删 redraw 历史只降 4%，真正解法是手牌折叠+对手分桶（v4 抽象，4.36M→31K，见 `收敛优化设计.md` §2）。v4 + Linear CFR 重训 1M + 纯化推理（argmax + never-fold）后，CFR 在全部 5 个 baseline 及头对头上超越旧 Q-learning bot（头对头 +0.096，n=1500）。详见 CHANGELOG 2026-07-02 条目。

## 4.6 为什么 redraw 要做成迭代（v3 改动）

**原 v2 设计**：每 round 单次 redraw（选一个 5-bit bitmask 就结束）

**问题（用户原话）**：手牌 5,6,7,8,K，open-ended 4 张顺子。
- 单次换 K 完成顺子概率：8/47 ≈ **17%**
- 我哪怕剩 6 次配额也用不上，本 round 就这一发子弹
- 跨 round 攒下次也只能开一枪，所以攒着毫无意义

**v3 修正**：每 round 可迭代 redraw，0 表示 STOP。

现在你能一直换 K 直到中或者放弃。同样 5,6,7,8,K 例子：
- 每次失败可以再换 K
- 7 次配额可以试 7 次
- 累计完成概率：$1 - (39/47)^7 ≈ $ **72%**

**这个改动一下让 redraw 配额变成真正有意义的资源**。

## 4.7 三个核心策略博弈点（v3 后）

1. **追牌深度**（chase depth）：一直换直到中 vs 见好就收
2. **跨 round 资源投资**：本 round 烂 → fold 攒配额给下 round
3. **行为 leak 信息**：你换牌的次数和位置都会被对方观察到 → 隐含 bluff 空间

# 第五部分：工程概念

## 5.1 同时出牌如何建模成博弈树

**问题**：FOLD phase 是同时出牌，但博弈树天生是序列结构。

**OpenSpiel 标准模式**：把同时出牌**改建模为**序列出牌 + **不让第二个玩家看到第一个的选择**。

具体：
- 用 `_waiting_for` 字段记当前轮谁
- P1 先决定，存进 `fold_this_round[0]`，但**不更新 observation 让 P2 看到**
- P2 决定后，两个一起 reveal
- 设 `_fold_revealed = True`，这时 observation 才暴露双方的 fold 选择

实现在 `cfr/env/game.py` 的 `apply` 函数。

## 5.2 信息隔离的实现方式

**原则**：**物理上 None**，不是「flag 起来但仍然把数据传过去」。

为什么？因为 CFR 在 info set encoding 时会序列化整个 observation。如果数据真的存在 observation 里（哪怕加了 `is_hidden=True`），稍微一不小心就会被纳入编码，造成信息泄露。

**实现**：`observation()` 函数主动构造一份只含可见信息的 `Observation` 对象，hole cards 槽位填 `None`，对手 pending redraw action 不放进去。

参考 `cfr/env/game.py:214-262` 的 `observation()` 方法。

## 5.3 Canonical Info Set Encoding（Phase 1 任务核心）

「canonical」= 「规范化」。任务：把 `Observation` 对象 → 一个唯一的 string key，给 CFR 用作 regret/strategy 表的 key。

**为什么不能直接 `str(observation)`**：
- 牌的顺序无关：[♠A, ♥K, ♦5] 和 [♥K, ♠A, ♦5] 表示同样的手 → 必须排序
- 花色无关性：如果 5 张牌不构成同花/同花顺，花色完全不影响牌型 → 可以"抽象掉"花色
- 但**部分场景花色相关**：4 张同花差 1 张到 flush 时，花色信息变成决策相关 → 不能简单抹掉

### 项目选用方案：7 元组骨架 + v2/v3 扩展

**历史背景**：原 v1 项目（Q-learning 时代）在 `model/poker_env.py::_get_state()` 设计了 7 元组优化状态表示，用 hand-crafted 特征大幅压缩状态空间：

```python
(HandRank, TopCard, SuitedMask, StraightMask, RemainingRedraws, PlayerWins, OpponentWins)
```

这套特征跟人类看牌的方式高度一致（"我有对子吗？""差几张同花？""差几张顺子？"），对 poker 决策极其友好。Phase 1 沿用这套思路，但需要扩展加入 v2/v3 新增的信息（对手 face-up、fold history、iterative redraw 序列）。**具体字段表见 `model_improvement_plan.md` §6 Phase 1**。

### 关键设计：StraightMask 加 draw_type 1 位

原 v1 的 `StraightMask` 只标"哪些位置在顺子里"，**不区分**：

| 类型 | 例子 | 完成方式 | 命中率 |
|---|---|---|---|
| open-ended | 8, 9, T, J | 缺 7 **或** Q | ~17% |
| gutshot | 8, 9, J, Q | 只缺 T | ~8.5% |

两种局面策略差很多（open-ended 该一直追、gutshot 该见好就收）。**加 1 位 `draw_type` ∈ {0=none, 1=open-ended, 2=gutshot, 3=already-straight}** 解决这个信息丢失，状态空间只翻 ~4 倍。

### 关键设计：对手 face-up 的花色编码必须跟自己花色对齐

对手每张 face-up 牌的花色，**不能**独立编码（独立编码丢失"对手和我同花色"这种关键信息）。

做法：每张 face-up 的花色编码为「**与我 dominant suit 同 / 与我 dominant suit 异**」 2 个值。这样 CFR 能识别：
- "对手 3 张面牌都跟我同花色" → 对手在追同花 → 警觉
- "对手面牌跟我无关花色" → 对手没在追同花

### 为什么不走完全无损方案

完全无损方案（raw ranks + canonical suit renaming）状态空间约 10⁷-10⁸，单机训练 tractable 但需要几天。

本方案约 10⁵-10⁶，几小时收敛。代价是 open-ended/gutshot 之外的极少数边角信息丢失（接受）。如果训完后效果不够强，方案可以平滑升级到无损方案（strict refinement）。

## 5.4 Self-play 训练

**做法**：让 agent 跟自己（或自己的历史版本）打。

**为什么自然契合 CFR**：
- CFR 本来就是双方"对弈中互相调整 regret"
- 我们 self-play 时两个 traverser 角色交替（一次 P1，一次 P2），同步更新两边的 regret 表
- 不需要外部对手，Nash 均衡是 self-play 的不动点

**实操**（Phase 3）：
- 训练循环每次 sample 一个 game tree path
- 两个 traverser 各跑一次 External Sampling
- 累加 regret + strategy_sum
- N 次迭代后取 average strategy = 最终模型

## 5.5 Kuhn Poker 验证

**Kuhn Poker** 是 3 张牌（J/Q/K）的 toy 扑克，info set 数量小（≈12），**Nash 均衡有解析解**：
- P1 拿 J：bet 概率 1/3
- P1 拿 K：bet 概率 1
- ……（完整解可以在论文里查）

**我们 Phase 2 的中间检查点**：先在 Kuhn Poker 上跑 MCCFR，**确认收敛到已知 Nash**（exploitability < 0.01），再去跑我们自己的游戏。

**为什么这个检查点关键**：MCCFR 实现错了，跑我们游戏不会有直接报错信号——你会得到一个看起来"在训练但效果不对"的模型，浪费一周时间。Kuhn 上验证可以 30 秒发现 bug。

### Exploitability 是什么 + 怎么算

**定义**：
$$
\text{exploitability}(\sigma) = \text{BR}_0\_\text{value}(\sigma_1) + \text{BR}_1\_\text{value}(\sigma_0)
$$
其中 $\text{BR}_p\_\text{value}(\sigma_{-p})$ = 玩家 $p$ 在 $\sigma_{-p}$ 固定下，遍历所有可能策略能达到的最大期望收益。

**意义**：在零和游戏中，Nash 策略组合 $\sigma^*$ 满足 exploitability = 0（因为零和：$\text{BR}_0 + \text{BR}_1 = V + (-V) = 0$）。非 Nash 策略 exploitability > 0，**值越大越好剥削**。

**正确性陷阱**：BR 策略必须是 **info set → action 的函数**，同一 info set 下不同 (真实手牌) 必须取相同动作。若在 game tree 每个 $(hands, history)$ 节点独立 $\max$，等于让 BR 看到对手底牌作弊，**算出来是 BR 上界而非真实 BR**。Phase 2 实现时踩过这个坑（v3-phase2-exploit-fix）：用 brute-force 枚举所有 $2^{|I|}$ 个 info-set 策略指派来强制约束。

**Kuhn 规模**：每个玩家 6 个 info set → $2^6 = 64$ 个纯策略候选，brute-force 完全够。对我们主游戏规模太大，将来要换 LP 或 iterative best response。

### 采样 BR（Phase 3 主游戏用）

主游戏 info set 估算 10⁷+，brute-force 2^(10⁷) 不可行；game tree DP 也不行（~10⁶⁰ 路径）。Phase 3 用 **1-ply lookahead Monte Carlo BR** 作 exploit 的 lower bound：

```
对每个玩家 p：
  N 局：
    每个 p 的决策：枚举所有 legal action a
      跑 K 次 rollout（从 (state, a) 出发，双方都按 σ_avg）
      Q_hat(state, a) = K 次 rollout 终局 utility 的均值
    取 a* = argmax_a Q_hat
  N 局终局 utility 取均值 = BR_p_value 估计

exploit_sampled = BR_0_sampled + BR_1_sampled
```

**为什么是 lower bound**：rollout 里 p 也用 σ_avg（不用 BR），等于"我深度上不再优化，让 1-ply lookahead 说了算"。真正的 BR 会在每个 state 都 lookahead → 比这个估计大。所以 sampled_exploit ≤ true_exploit。

**用途限制**：作为训练时趋势指标够用（exploit 在降说明 σ 在变 less exploitable）。不能当绝对数值发论文。

### Phase 2 实现验证（已完成）

跑 10⁵ External Sampling MCCFR 迭代后：
- exploit = 0.0027（门槛 0.01）✓
- 训出的策略与 Kuhn 解析解逐项匹配（α ≈ 0.237）：
  - P0 K first bet 0.727 ≈ 3α
  - P1 J after check bluff 0.336 ≈ 1/3
  - P0 Q after check-bet call 0.575 ≈ α + 1/3

### Phase 3 实现验证（已完成）

跑 10⁶ Outcome Sampling MCCFR 迭代（Kuhn 上）：
- exploit ≈ 0.006-0.015（OS 收敛比 ES 慢一个量级是已知事实）
- 训出策略匹配 Nash family（α ≈ 0.14，3α ≈ 0.42 K bet；Q@0 check；Q@1 call ≈ 1/3 = 0.357）

PokerGame 上：
- ~3ms/iter（ES 完全跑不动 → OS 切换的根本理由）
- 5k iter info set 数线性增到 ~25k

### Phase 3 关键经验教训

1. **External Sampling 在 32-action 上挂掉**：主游戏 REDRAW 阶段满 budget 32 个 action，traverser 全枚举 + 可迭代多次 → 32^k 量级。单 iter 跑不完。**只能走 Outcome Sampling**（详见 §3.7.5）。
2. **OS 的 IS correction 容易写错**：`child_value / sample_dist[sampled]` 这一步漏了 → 收敛卡死 exploit=0.33。OpenSpiel python 是参考实现的金标准。
3. **defaultdict 用 lambda 不能 pickle**：改成模块级 `_float_dict` 函数。
4. **读操作不能触发 defaultdict 创建**：`get_strategy` / `average_strategy` 用 `.get(info_set, {})` 替代 `[info_set]`，否则 eval rollout 一调用就灌爆 info_set 计数。
5. **exploit 评估降级**：主游戏 brute-force / game tree BR 都不可行 → Phase 3 用采样 BR（1-ply lookahead Monte Carlo，§5.5）作 lower bound。Phase 4 还会补 rule panel 胜率指标作为绝对强度判据。

### Phase 4 关键经验教训

1. **fold 是设计冗余**：原 v2 修正只挪了 fold 的位置，但没解决支配问题。play+STOP 不消耗预算，期望严格弱占优 fold。详见 §4.5.5。
2. **rule panel 的价值在"可解释验证"**：故意保留 AlwaysCall + Tight 这种被支配策略 agent，目的是让 vs-CFR 胜率成为 §4.5.5 的可观察指标（CFR 学到对手 fold 倾向就 play 偷局 → vs Tight 胜率应 ≥ 70%）。
3. **avg strategy ≠ 当前 strategy**：CFR agent 推理时必须用 `average_strategy`（Nash 收敛量），不是 `get_strategy`（regret matching 的当前迭代量）。这是 CFR 家族容易写错的关键点。
4. **测试 input 抽象**：人机 CLI 测试用 `_make_input_feeder` 把多步输入封装成 iterator，避免每个测试写 monkeypatch 状态机。
5. **alternate seats**：play_match 偶数局 a=seat0、奇数局 a=seat1，中和先手优势。这是博弈评估的标准做法，否则胜率会被先手偏置污染。
